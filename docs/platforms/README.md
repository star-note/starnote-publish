# 平台调研：国内平台

这里每个平台一份开发资料，写的是平台的开放能力、编辑器、发布字段、规则、风控，以及和浏览器插件逐项对照的结果。这些内容给开发看。面向用户的「发布指南」在 starnote-docs 的 `official-guides/` 下。

- 调研日期：2026-10-29。
- 资料来源：官方文档、公开资料，以及开源插件源码（Wechatsync v2、MultiPost、COSE、zhihu_obsidian、xiaohongshu-mcp）。
- 文中的写法：
  - 「待实测」：要登录后在真实页面上核实。
  - ⚠️：只有第三方说法。

**底线**：辰记在每个平台能填的字段，不能少于填得最全的插件。

| 平台 | 官方 MCP | 个人可用的官方发布 API | Webhook | 编辑器 / 正文格式 | 辰记现状 | 对标对象 |
|---|---|---|---|---|---|---|
| [微信公众号](wechat.md) | 无 | 只能存草稿（个人号能不能调待实测）；发布接口 2025-07 起只对认证企业开放 | 有（发布结果事件，需要认证且配置服务器） | ProseMirror，只接受 HTML，图片必须转存到 mmbiz | 桌面端适配器，存进草稿箱 | MultiPost（封面会做三种比例裁剪） |
| [知乎](zhihu.md) | 无 | 无（开放平台只能发圈子想法） | 无 | Draft.js，正文用 HTML | 桌面端发布台 | zhihu_obsidian |

| [CSDN](csdn.md) | 无 | 无 | 无 | Markdown 或 CKEditor；接口要网关签名 | 桌面端发布台 | MultiPost |

## 统一做法

1. **默认走发布台**。用的是用户自己的登录态：辰记把所有字段填好，「发布」由用户自己点。辰记不自动点发布，也不批量发。
2. **签名一律不复刻**。头条的 `a_bogus`、小红书的 `x-s`、B 站的 wbi、CSDN 的 `x-ca-*`，统一在平台页面内发请求，由页面自己的 JS 加签；做不到的平台就只做页面填表（DOM）。
3. **能走官方通道就走官方**：
   - 语雀：用户自己的 Token。
   - 百家号：用户自己的 app_token。
   - 认证企业公众号：AppID + 辰记服务器出口 IP。
4. **控制发布节奏**：
   - 站点脚本里的 `pacing` 是产品自己定的保守值：请求之间隔 0.8–4.5 秒，两篇至少隔 30 分钟，每天最多 5 篇。
   - 平台的上限在不同来源里说法不一，以平台页面实际提示为准，不要写死。
5. **验证码、滑块交给用户**。遇到 `challenge` 时，把平台页面原样交给用户处理，不做任何绕过。
6. **外链**。头条、百家号、B 站、小红书对外链很敏感，渲染时默认把链接改成纯文字，并提醒用户。

## 每个平台都要记的四件事

1. **官方通道**：有没有开放平台、API、MCP、Webhook，个人账号能不能用。
2. **风控**：页面靠什么识别自动化，包括签名参数、安全 SDK、cookie、设备指纹，以及验证码在什么情况下出现。辰记按下面的方式在规则内运行，不伪造签名，不绕过验证：
   - 用用户自己的登录态，在平台自己的页面里操作，签名由页面自己的代码加；
   - 控制发文节奏；
   - 遇到验证就交给用户处理。
3. **发布后的数据**：阅读、点赞、评论、收藏从哪里拿。优先级如下：
   - 官方数据接口（`source: 'official-api'`）；
   - 其次是创作者后台的数据页及它调用的接口（`'console'`，用登录态读）；
   - 最后是公开的文章页或接口（`'public'`）。

   适配器实现 `Adapter.fetchStats`，由桌面端每 6 小时采一次，通过 `POST /me/platform-stats` 上报（见 `packages/core/src/insights.ts`）。**目前国内四个适配器都还没实现 `fetchStats`。**

4. **变现**：
   - 平台有哪些收益方式：流量分成、广告、带货、付费内容、赞赏、品牌任务等；
   - 每一项怎么开通，门槛是等级、粉丝、原创还是实名；
   - 收益数据在哪里看。

   辰记据此做两件事：
   - 在绑定页显示「离下一个变现门槛还差多少」；
   - 发布表单里，跟收益有关的开关（赞赏、投放广告、带货卡片、付费）只对已开通的账号显示。

## 发布后怎么拿到文章链接

平台都会给链接，但很多要等审核通过才能公开访问。另外，最后的「发布」是用户自己点的，所以辰记得自己去把链接找回来，记进 `platform_posts`，后面统计数据要用。

| 平台 | 文章链接 | 拿法 |
|---|---|---|
| 知乎 | `zhuanlan.zhihu.com/p/{id}` | 草稿阶段就有 id，发布后页面跳到 `/p/{id}`（站点脚本的 `published.urlMatch`） |
| 掘金 | `juejin.cn/post/{id}` | 发布后跳到 `/published` 或 `/post/{id}`；审核通过后才公开 |
| CSDN | `blog.csdn.net/{用户名}/article/details/{id}` | 发布后跳到 `mp.csdn.net/mp_blog/creation/success/{id}`；草稿阶段的 `articleId` 就是同一个 id |
| 公众号 | `mp.weixin.qq.com/s/{key}` | 存草稿时没有链接；群发或发表、审核通过后才有。到「发表记录」里取 ⚠️ |
| 头条号 | `www.toutiao.com/article/{id}/` ⚠️ | 审核通过后才有。去「作品管理」列表按标题对上 |
| 百家号 | `baijiahao.baidu.com/s?id={id}` ⚠️ | 审核通过后才有，去「作品管理」里取 |
| B 站 | `www.bilibili.com/opus/{id}`（旧链接是 `/read/cv{id}`） ⚠️ | 审核通过后才有，去「内容管理 → 专栏」里取 |
| 微博头条文章 | `weibo.com/ttarticle/p/show?id={id}` ⚠️ | 发布后会同时生成一条微博；去「发布历史」里取 |
| 小红书 | `www.xiaohongshu.com/explore/{noteId}` ⚠️ | 审核通过后才有；网页上看笔记要带 `xsec_token` |
| 语雀 | `www.yuque.com/{用户}/{知识库}/{slug}` | 接口返回结果里直接有，不用审核 |

辰记的做法：
1. 能从发布后的跳转地址里取到 id 的，就当场记下。
2. 取不到的（需要审核的平台），发布台关掉以后，每隔一段时间用登录态读一次平台的「作品管理」列表，按标题和发布时间对上这篇文章，拿到 id 和链接。和 `fetchStats` 共用同一次读取，读的同时把状态（审核中、已发布、未通过）也一起带回来。
3. 用户也可以自己把链接粘贴回来（和 CSDN「录入地址」的做法一样）。
