# 国内平台调研总结（2026-10-29 / 30 实测）

这份总结来自 16 个国内平台的单独文档（见同目录）。内容分四部分：

1. 各平台用什么编辑器；
2. 发布表单最少要填什么、哪些交给 AI；
3. 平台的风控里，有哪些辰记可以低成本借来保护自己；
4. 桌面端发布台要怎么改。

## 1. 编辑器类型

| 编辑器 | 平台 | 辰记怎么往里填 |
|---|---|---|
| **ProseMirror / tiptap** | 公众号（另有 `__MP_Editor_JSAPI__`）、头条号、小红书（图文正文和长文）、B 站专栏（新版）、微博头条文章、抖音文章、企鹅号 | 能调平台自带接口的，优先用接口：公众号用 `mp_editor_set_content`。没有接口的，在编辑器里粘贴 `text/html`。直接改 `innerHTML` 不行，内容进不了编辑器的文档模型 |
| **Draft.js** | 知乎 | 用草稿接口提交 HTML（现在就是这么做的）；也可以粘贴 Markdown，平台会弹「确认并解析」 |
| **CodeMirror / ByteMD（Markdown）** | 掘金 | 调用编辑器的 `setValue(markdown)`，或者用草稿接口传 `mark_content` |
| **Markdown（contenteditable）+ CKEditor（富文本）** | CSDN | 用 Markdown 编辑器；新文章自带一篇示例，要整篇替换掉 |
| **UEditor（iframe）** | 百家号 | 调 `UE_V2.instants[...].setContent(html)` |
| **Quill** | 搜狐号（支持 Markdown 语法输入） | 粘贴 HTML，或者直接输入 Markdown |
| **自研富文本或 Markdown** | 简书（`.kalamu-area`，按用户设置的默认编辑器决定） | 先读用户的默认编辑器设置，再决定填 HTML 还是 Markdown |
| **Lake（语雀自有格式）** | 语雀 | 官方接口直接接受 Markdown 或 HTML |
| **不用网页编辑器** | 博客园（MetaWeblog 接 Markdown）、网易号（官方接口接 HTML）、百家号官方接口（HTML） | 直接调接口 |
| **文件导入** | 抖音文章（docx / txt / md）、小红书长文（只能导入公众号链接） | 抖音优先走文件导入：辰记导出 `.md` 文件，交给页面上的上传框 |

小结：
- 国内平台基本都换成了 **ProseMirror 系**，和辰记自己的编辑器（tiptap）同源。所以「渲染 HTML → 粘贴进编辑器」这条路最通用。
- 知乎、掘金、CSDN 有草稿接口，可以不经过编辑器直接提交。

## 2. 发布表单：最少要填什么

原则：
- **表单尽量少**。凡是 AI 能填的就让 AI 填，用户只做确认。
- **声明类字段（原创、AI、创作来源）只给出选项，不预设值**，由用户自己选。
- 能用平台默认值的字段，辰记不管。

字段分四类：

| 类别 | 字段 | 怎么处理 |
|---|---|---|
| **AI 预填，用户确认** | 标题（按各平台字数截断或改写）、摘要 / 导语、标签 / 话题（先拿平台的联想或推荐列表做候选，AI 从中选）、分类（从平台分类列表里选）、封面（从正文图片中挑，或用辰记卡片生成，按平台比例裁剪） | 发布面板每个平台一行。AI 填好后可以展开修改 |
| **用户选（不预设）** | 原创声明、创作声明 / AI 声明 / 内容来源、可见范围、定时发布时间、首发（头条，与多平台同发冲突）、关注后阅读（微博） | 列出平台原有的选项，加一句平台规则说明 |
| **只在账号有这项权益时才显示** | 赞赏、投放广告、付费、带货卡片、专栏 / 合集 / 文集（从账号已有的列表里选） | 由能力接口决定显示与否，例如百家号的 `getabilityinfo`、知乎的权益页 |
| **不管（沿用平台默认）** | 评论开关、允许复制、平台推荐、同时发布微头条、自动生成播客、地点、群聊、投票、配乐、活动投稿等 | 不进表单；用户想改，就在发布台的平台页面里自己改 |

各平台必填字段，以及它们和插件的对比：

| 平台 | 必填（辰记必须填上） | 现有插件最多能填到哪 | 辰记要多做的 |
|---|---|---|---|
| 公众号 | 标题（64 字）、正文、封面 | MultiPost：作者、摘要、三种比例封面 | 原创 / 创作来源这类声明列给用户选；赞赏和合集按账号权益显示 |
| 知乎 | 标题（100 字）、正文、话题（平台会自动推荐） | zhihu_obsidian：话题、封面、声明 | 话题用平台推荐的结果再加上 AI 选的；投稿到问题 |
| 掘金 | 标题（80 字）、正文、分类、标签（数量按等级 1–3 个）、摘要（≤100 字，平台能自动生成） | **所有插件都不填分类、标签、摘要** | 这三项全部由 AI 预填 |
| CSDN | 标题（5–100 字）、正文、标签（最多 7 个）、文章类型 | MultiPost：标签、分类、封面、定时 | 标签数量跟着等级走；每天剩余篇数读平台给的值 |
| 头条号 | 标题（2–30 字）、正文、封面方式 | MultiPost：标题、正文、封面 | 摘要、作品声明 |
| 百家号 | 标题（2–64 字）、正文、封面 | MultiPost：单图横竖裁剪、摘要 | 按能力接口决定显示原创、付费等选项 |
| B 站专栏 | 标题（≤50，建议 30 字以内）、正文 | MultiPost 填的分类、标签是**旧接口字段，已经失效** | 按新版填：封面、话题、文集、AI 声明（用户选） |
| 微博头条文章 | 标题（32 字）、正文 | MultiPost：导语、16:9 封面 | 关注后阅读（用户选），提示未认证账号每天只有 1 篇能用 |
| 小红书图文 | 1–18 张图、标题、正文（1000 字） | xiaohongshu-mcp：话题、定时、可见范围、原创 | **由辰记生成卡片图**（`versions/xhs`），话题从联想列表里点选 |
| 抖音文章 | 标题（30 字）、正文、封面 | 没有插件支持 | 导入 md 文件；摘要（30 字）、话题（最多 5 个）由 AI 填 |
| 搜狐号 | 标题（5–72 字）、正文、**创作声明（必选）** | 没有 | 读 `publishLimit` 显示今天还剩几篇 |
| 企鹅号 | 标题（5–64 字）、正文 | 没有 | 标签（最多 9 个）、分类由 AI 填 |
| 简书 | 文集、标题、正文 | COSE 只填标题和正文 | 文集从列表里选 |
| 语雀 | 知识库、标题、正文 | Wechatsync 把知识库写死了 | 知识库从列表里选；会员走官方接口 |
| 博客园 | 标题、正文（走官方接口） | 无 | 走令牌，一键发布 |
| 网易号 | 标题（11–30 字）、正文、分类（走官方接口） | 无 | 注册第三方开发者后，走 OAuth 一键发布 |

**比插件强在哪里**：插件只把内容搬过去。辰记还会：
- 按各平台的字数和规则改写；
- 预填平台的必填项；
- 读取账号的等级、权益和当天剩余篇数；
- 发布后把链接和数据收回来。

## 3. 平台风控里辰记能低成本借鉴的

**平台都在用的手段**（按实现成本从低到高）：
1. **频率和配额**：每天能发几篇（搜狐 `publishLimit`、CSDN / B 站按等级）、接口限流（知乎开放平台 10 QPS）。
2. **CSRF 令牌**：cookie 和请求头双重校验，比如知乎的 `_xsrf` / `x-xsrftoken`、掘金的 `x-secsdk-csrf-token`、B 站的 `bili_jct`。
3. **关键 cookie 设成 httpOnly**：所有平台的登录态 cookie，页面脚本都读不到。
4. **按等级、实名、绑定开放能力**：CSDN 要绑定微信才能发文；头条、搜狐、网易要实名；B 站要 LV1；新号限制标签数和篇数。
5. **验证码按风险触发**：腾讯防水墙（搜狐、企鹅号）、阿里云 WAF 滑块（语雀）、字节验证中心。平时不出现，异常时才弹。
6. **请求签名和设备指纹**：字节的 `a_bogus` / `msToken`（`bdms`）、小红书的 `x-s`（`_webmsxyw`、`xhsFingerprintV3`）、B 站 wbi、CSDN 网关签名。成本高，辰记不需要。

**辰记现状**（starnote-api）：
- 已有固定窗口限流（`app/core/ratelimit.py`），覆盖登录（10 次/分钟、60 次/小时，按 IP）、注册、OAuth、评论、AI（20 次/分钟，按用户）、短链、API Key（60 次/分钟）。
- **读取类接口没有限流**，比如笔记列表、笔记详情、导出、公开博客页、搜索。这正是批量越权抓取最容易下手的地方。

**建议的加固**（按成本从低到高，另写 SPEC 落地）：

| # | 措施 | 防什么 |
|---|---|---|
| 1 | **读取接口按用户和 IP 限流，并设每日配额**：笔记详情、列表、导出、搜索、公开文章页、RSS / sitemap 之外的 JSON 接口 | 用合法账号或 API Key 批量拉数据 |
| 2 | **越权测试补齐**：所有按 id 取资源的接口都要校验归属，包括笔记、发布记录、资源、群组。对象 id 不可枚举（UUID 或短 id 加随机）；公开文章只按 `short_id` 访问 | 改 id 越权读取别人的文章和数据 |
| 3 | **会话加固**：登录态 cookie 设 httpOnly、Secure、SameSite；refresh token 轮换，被重复使用时视为被盗，吊销整个会话链；改密码或异地登录时吊销所有会话；「登录设备」列表可以踢下线 | 偷 token 后长期使用 |
| 4 | **异常登录按风险加验证**：同一 IP 多账号、短时间失败多次、新设备加新地区时，才要求邮箱验证码或人机验证（Turnstile 一类），平时不打扰 | 撞库、批量注册 |
| 5 | **API Key 做细粒度 scope**（只读 / 发布 / 某个群组），加上用量面板和异常告警；MCP 和桌面工具都用带 scope 的 Key | 桌面工具、AI 代理拿到 Key 后权限过大 |
| 6 | **公开页反爬**：对公开博客页，按 IP 和 ASN 的访问速度分级处理（正常 → 降速 → 验证），机房 IP 段更严；robots 和 `ai.txt` 声明 AI 抓取策略；正文可选加不可见水印，便于追查搬运 | 爬虫、AI 训练抓取整站 |
| 7 | **审计和告警**：记录导出、批量读、新设备登录；超过阈值就告警，并通知用户本人 | 发现得晚 |
| 8 | **签名和指纹**（参照平台）：成本高，影响正常用户和开放 API，暂时不做 | — |

## 4. 桌面端发布台（Electron）要改的

现状（starnote-desktop）：
- `publish-desk` 和 `platform-login` 的 `setWindowOpenHandler` 只处理白名单内的地址，其余一律 `deny`，`security.ts` 的全局兜底也是拒绝。
- 结果是：遇到「先 `window.open()` 开一个空白窗口、再设置 `location`」这种写法（企鹅号微信扫码、公众号「新的创作」、抖音「我要发文」、网易号开发者平台），打开的空白窗口直接被拒，页面拿到 `null`，接着就报错。

要做到：**平台页面里的所有操作都能正常用，弹窗不拦**。

1. **弹窗**：
   - 发布台和登录窗口里的 `window.open`（包括地址为空或 `about:blank` 的）改成 `action: 'allow'`，在**同一个会话分区**里开一个子窗口，大小跟随父窗口。这样页面后面对 `location` 的赋值和 `opener.postMessage` 都能正常工作。
   - 子窗口如果跳到平台白名单以外的地址，交给系统浏览器打开（例如帮助文档）。
   - `alert`、`confirm`、`prompt` 和文件选择框用 Electron 默认行为，不拦。
2. **输入**：
   - 页面上不要叠透明层：点击、长按（mousedown 不放）、拖动（滑块验证、拖拽排序图片、拖动封面裁剪框）、滚轮、键盘、输入法都要原样传到页面。
   - 允许把系统里的文件拖进页面（上传图片、导入 md），不要拦 `will-navigate` 中的 `file://` 拖放事件。
3. **会话和兼容**：
   - 每个平台、每个账号用独立分区（现在就是这样）。
   - User-Agent 用正常的 Chrome UA。
   - 不禁用第三方 cookie，扫码登录和腾讯防水墙要用。
   - CSDN 绑定页依赖 `document.domain`，无法兼容，引导用户去自己的浏览器完成。
4. **单端登录提醒**：小红书等平台同一账号只能在一个网页端登录，绑定时提示用户。
